# 필수 키 NULL과 데이터 정정 / not_null

문서 ID: rb-quality
버전: 2
수정일: 2026-10-20
자료 유형: 직접 작성한 운영 절차

## 증상
not_null, null_counts, order_id, customer_id, null rows, dbt_test, quality profile

## 확인과 원인 구분
선택 실행의 검사 결과와 로그에서 실제 실패한 키를 확인하고 현재 같은 테이블의 제한된 프로필을 대조한다. 현재 NULL 건수를 과거 실패 건수로 단정하지 않는다.

## 사람의 조치
개발자가 원천 매핑과 누락 경로를 확인한다. 원본을 보존하고 승인된 정책에 따라 키를 정정하거나 잘못된 레코드를 격리한다.

## 선행 조건
업무 키 정의와 정정·격리 정책이 필요하다. 임의 삭제나 임의 키 생성으로 통과시키지 않는다.

## 검증
새 실행의 not_null와 unique가 모두 통과하고 태스크 성공, 건수·금액 정합성이 유지되는지 확인한다.

## 적용 제외
컬럼이 없거나 DB에 접속하지 못한 상태를 NULL 문제로 단정하지 않는다. 단순 재시도는 데이터 정정이 아니다.
