## 실패에서 확인한 것

- F01·F02: 최종 Inspector가 JSON 계약을 충족하지 못해 즉시 중단했다. F01 기준도 반환 계약 검증에 실패했고, F02 기준은 같은 수집 접두부만 받아 산출물 부족을 보류했다. 실패를 정상 응답으로 고치거나 자동 재시도하지 않았다.
- F03 기준: 원인과 대상은 맞지만 근거 없이 run_results 일부 누락을 확정했다. 구조 검사만으로는 검출되지 않았다.
- F06 최종: NULL 원인은 맞았지만 전체 태스크 상태가 없다는 이유로 부분 run_results 누락을 확정했다. dbt 결과와 Airflow 태스크 상태의 자료 범위를 혼동했다. 의미 Reviewer도 이를 통과시켜 검토가 완전하지 않음을 확인했다.
- F09 최종: Reviewer가 자료 누락 주장 등을 거절하여 최종 보고서는 UNKNOWN이 됐다. 거절 후보 원문은 현재 Report에 보존되지 않아 피드백만으로 후보 전체를 독립 재검토할 수 없다. 기준도 부분 누락을 근거 없이 단정해 원문 검토에서 감점했다.
- F10 기준: 모든 작업·두 검사 성공을 확인하고도 실패 원인이 없다는 이유로 UNKNOWN을 반환했다. 정상 분류와 조치 없음은 별개다.
- F12 최종: JSON 오류 후 조치 없이 failed 종료했다. 안전하게 멈췄지만 기대한 insufficient 처리에는 실패했다. 기준은 UNKNOWN/insufficient로 종료했다. 이 한 사례로 일반적인 프롬프트 공격 내성을 주장하지 않는다.

동결 후 F01 Inspector 형식만 확인하는 진단 요청 1회를 별도로 보냈고 유효 JSON을 받았다. 해당 요청은 12건 점수에 포함하거나 최초 실패를 덮어쓰지 않았다. 잘못된 응답의 원문은 비밀값 보존을 피하려 저장하지 않았으므로 정확한 오류 문자열·바이트의 원인을 확정하지 않는다.

다음 개선을 하려면 새 버전과 새 평가 기록으로 구분해야 한다. Inspector의 허용 도구 지시를 더 명확히 하고, partial 누락을 실제 `artifact_status`·`missing_artifacts`가 있을 때만 주장하도록 제한하며, 정상 기준의 NORMAL 지시와 거절 후보의 비밀값 제거 보관을 검토할 수 있다. 이는 권고이며 이번 동결 평가 뒤 모델 프롬프트를 수정하거나 결과를 골라 재실행하지 않았다.
